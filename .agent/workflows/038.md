# [Workflow-038] ユーザーデータ・設定ファイルの保存場所明示 (Clarify User Data Location)

## 概要

アプリケーションが生成・管理するユーザー固有のデータ（設定ファイル、データベース、ログ、マクロ定義など）の物理的な保存場所を、ユーザーが容易に参照できる公式ドキュメント（主に `README.md`）に明記するためのルールです。

これはユーザーの「データコントロール権（バックアップ、完全削除、別環境への移行）」を保障し、トラブルシューティング時の自己解決能力を高めるために不可欠です。

## 課題 (Why)

- **ブラックボックス化の回避**: 「設定がどこに保存されているかわからない」状態は、アンインストール時のゴミファイル残留や、PC 移行時のデータ損失リスクを招く。
- **トラブル対応**: 設定ファイル破損時に、ユーザー自身でファイルを削除してリセットする等の対応が取れなくなる。

### ❌ Bad Example

- `README.md` にインストール方法と機能説明しかない。
- 設定がアプリ内部（コード内やアクセス不能な領域）のみで完結しているかのような記述。
- 「設定は自動保存されます」としか書かれていない。

### ✅ Good Example

- `README.md` に独立したセクション「データ保存場所」「設定ファイルの場所」がある。
- OS 標準のパス表現（`%APPDATA%`, `~/.config` 等）を用いて具体的な場所が示されている。
- 主要なファイル名とその役割がリストアップされている。

## 手順 (Step-by-Step)

### 1. 保存場所の特定

実装コードを確認し、実際にデータが保存されているパスを特定します。

- **Electron**: `app.getPath('userData')`
- **Node.js**: `process.env.APPDATA`, `os.homedir()` 等
- **Web**: LocalStorage, IndexedDB 等

### 2. ドキュメントへの記載

`README.md` （またはそれに準ずるメインドキュメント）に以下の情報を記載します。

#### 必須項目

- **ディレクトリパス**: OS ごとの標準的なパス（Windows なら `%APPDATA%\<app-name>`）。
- **目的**: バックアップ、リセット、デバッグなど、ユーザーがその場所にアクセスする動機。

#### 推奨項目

- **主要ファイルリスト**: `config.json`, `database.sqlite` など、重要なファイルの名前と役割。
- **手動操作の注意点**: 「編集時はアプリを終了してください」等の警告。

### 3. 表記テンプレート

```markdown
## 設定データの保存場所

本アプリの設定データは以下のディレクトリに保存されます。バックアップや手動リセット（削除）の際にご参照ください。

- **Windows**: `%APPDATA%\my-app-name`
- **macOS**: `~/Library/Application Support/my-app-name`
- **Linux**: `~/.config/my-app-name`

**主要なファイル**:

- `settings.json`: アプリケーション設定
- `data.db`: ユーザーデータ
```
