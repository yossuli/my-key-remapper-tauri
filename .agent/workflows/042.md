# [Workflow-042] 宣言的オブジェクトマッピング (Declarative Object Mapping)

## 概要

特定の値に基づいて結果を切り替えるロジックにおいて、`if-else` 文や連鎖した三項演算子は可読性が低く、拡張も困難です。
代わりに、オブジェクトリテラルを用いたマッピングと Optional Chaining (`?.`) を組み合わせることで、ロジックを宣言的なデータ構造として表現します。

## メリット

1.  **可読性**: 条件分岐が「データ（キーと値のペア）」として一覧化される。
2.  **拡張性**: 新しいケースを追加する際、オブジェクトにプロパティを追加するだけで済む。
3.  **安全性**: `undefined` チェックが Optional Chaining に内包される。

## Bad/Good Example

### Bad (If-Else / Switch / Ternary Chain)

```tsx
const getValue = (trigger: string, src: any) => {
  if (trigger === "typeA") return src.propA;
  if (trigger === "typeB") return src.propB;
  if (trigger === "typeC") return src.propC;
  return null;
};
```

### Good (Object Mapping)

```tsx
const getValue = (trigger: string, src: any) => {
  const map = {
    typeA: src?.propA,
    typeB: src?.propB,
    typeC: src?.propC,
  };
  return map[trigger] ?? null;
};
```

### Good (Safety Mapping)

`as` による型アサーションを避け、一度型定義された定数に代入してからアクセスします。

```tsx
const map: Record<string, any> = {
  typeA: src?.propA,
  typeB: src?.propB,
  typeC: src?.propC,
};
const value = map[trigger];
```

### Bad (Type Assertion)

```tsx
const value = (
  {
    typeA: src?.propA,
    typeB: src?.propB,
    typeC: src?.propC,
  } as Record<string, any>
)[trigger];
```

## 適用手順

1.  **分岐の特定**: `switch` 文や複数の `if` 文で値を返している箇所を特定する。
2.  **オブジェクト化**: 条件キーをプロパティ名、結果を値とするオブジェクトを作成する。
3.  **マッピング**: `mapping[key]` の形式で値を取得する。
