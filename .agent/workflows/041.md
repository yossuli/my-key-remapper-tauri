# [Workflow-041] 宣言的リマップ制御 (Declarative Remap Control / RemapDisabler)

## 概要

モーダルやフォーム入力時など、一時的にキーのリマップ機能を無効化したい場合、`useRemapControl` フックを使って `useEffect` 内で `disableRemap` / `enableRemap` を命令的に呼び出すのではなく、`RemapDisabler` コンポーネントを使用します。
これにより、リマップ制御のライフサイクル（マウント時に無効化、アンマウント時に復帰）がコンポーネントの配置そのものと同期し、コードが宣言的かつ堅牢になります。

## 原則

1.  **Declarative over Imperative**:
    - `useEffect` による手動制御は、依存配列の管理ミスやクリーンアップ漏れのリスクがあるため避ける。
    - コンポーネントツリーに `RemapDisabler` を配置することで、「この UI が表示されている間はリマップさせない」という意図を明確にする。

## Bad/Good Example

### Bad (Imperative Hook)

```tsx
const Modal = () => {
  const { disableRemap, enableRemap } = useRemapControl();

  useEffect(() => {
    disableRemap();
    return () => enableRemap();
  }, []);

  return <div>...</div>;
};
```

### Good (Declarative Component)

```tsx
import { RemapDisabler } from "@/components/control/RemapDisabler";

const Modal = () => {
  return (
    <div>
      <RemapDisabler />
      {/* ...コンテンツ... */}
    </div>
  );
};
```

## 適用手順

1.  **インポート**: `import { RemapDisabler } from "@/components/control/RemapDisabler";`
2.  **配置**: リマップを無効化したいコンポーネント（Dialog, Popover, Input Focus 時のラッパー等）の内部、または条件付きレンダリングブロック (`Show` / `Ternary`) の中に `<RemapDisabler />` を配置する。
3.  **確認**: コンポーネントが表示されるとリマップが止まり、非表示になるとリマップが再開されることを確認する。
