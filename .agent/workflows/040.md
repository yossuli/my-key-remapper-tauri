# [Workflow-040] 純粋データ Props による合成可能 UI パターン

## 概要

UI コンポーネントの柔軟性を高める際、Props として「完成済みのコンポーネント (ReactNode)」を渡すのではなく、「純粋なデータ (string, icon type 等)」を受け取り、コンポーネント内部で組み立てる設計を優先します。
これにより、呼出側のコードをシンプルに保ちつつ、UI の一貫性と責務分離（Inversion of Control の逆、カプセル化）を強化します。

## 原則

1.  **Primitive over Component**:
    - 可能な限りプリミティブな値 (`string`, `number`, `boolean`) や、データ型 (`LucideIcon`, データオブジェクト) を Props として定義する。
    - `title: ReactNode` よりも `title: string` + `icon: LucideIcon` を優先する。
2.  **Internal Composition**:
    - 渡されたデータに基づき、コンポーネント内部で適切なサブコンポーネント (`IconLabel` 等) を使用してレイアウトを組み立てる。
3.  **Declarative Branching**:
    - データの有無による表示切り替えは、内部で `Ternary` や `Show` などの制御コンポーネントを用いて宣言的に記述する (`Workflow-008` 準拠)。

## Bad/Good Example

### Bad (Component Injection)

呼び出し側がレイアウトを知っている必要があり、記述が冗長になる。

```tsx
// 定義
interface SectionProps {
  title: ReactNode;
}
const Section = ({ title }: SectionProps) => <div>{title}</div>;

// 利用側
<Section title={<IconLabel icon={User} label="ユーザー設定" />} />;
```

### Good (Pure Data Props)

呼び出し側はデータのみに関心を持ち、レイアウトはコンポーネントが責任を持つ。

```tsx
// 定義
interface SectionProps {
  title: string;
  icon?: LucideIcon;
}
const Section = ({ title, icon }: SectionProps) => (
  <div>
    <Ternary condition={Boolean(icon)}>
      <Then>
        <IconLabel icon={icon!} label={title} />
      </Then>
      <Else>
        <h3>{title}</h3>
      </Else>
    </Ternary>
  </div>
);

// 利用側
<Section title="ユーザー設定" icon={User} />;
```

## 適用手順

1.  **Props の見直し**:
    - `ReactNode` を受け取っている Props がある場合、それが「任意のコンテンツ」なのか「特定の構造（例：アイコン＋テキスト）」なのかを分析する。
    - 特定の構造であれば、Props を分解する（`title` + `icon` など）。
2.  **内部実装の修正**:
    - 分解した Props を受け取り、内部でサブコンポーネントを使ってレンダリングする処理を記述する。
    - 条件分岐には `Workflow-008` の制御コンポーネントを使用する。
3.  **呼び出し側の修正**:
    - コンポーネントを渡していた箇所を、データ渡しに変更する。

## 除外ケース (Exceptions)

- **完全な自由記述が必要なスロット**: `children` や、本当に任意の UI を差し込みたい場合（例：`renderRightAccessory`）は `ReactNode` が適切。
- ただし、その場合でも「メインのコンテンツ」とは区別し、明確な命名（`extra`, `footer` 等）を行うこと。
