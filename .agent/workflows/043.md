# [Workflow-043] 宣言的フック同期 (Declarative Hook Synchronization)

## 概要

データの取得や初期化を行うカスタムフックにおいて、コンポーネント側から `useEffect` 内で命令的にロード関数（`load()` 等）を呼び出すのではなく、フックの引数として「同期のトリガーとなる値」を渡し、フック内部で宣言的に状態を同期させます。

## メリット

1.  **カプセル化**: 同期のタイミングや依存配列の管理責任をフック内に閉じ込められる。
2.  **安全性**: コンポーネント側での呼び出し忘れや、不適切な依存配列による無限ループ・同期ズレを防げる。
3.  **簡潔さ**: コンポーネント側は「何が欲しいか（トリガー）」を渡すだけで済む。

## Bad/Good Example

### Bad (Imperative Sync)

呼び出し側がロードのタイミングを管理しなければならず、複雑。

```tsx
// useBindingConfig.ts
export function useBindingConfig() {
  const load = (id: string) => {
    /* ... */
  };
  return { load };
}

// Component.tsx
const { load } = useBindingConfig();
useEffect(() => {
  if (id) load(id);
}, [id, load]); // eslint-disable-line
```

### Good (Declarative Sync)

フック自身が「ID が変わったらロードする」という責務を持つ。

```tsx
// useBindingConfig.ts
export function useBindingConfig(id?: string) {
  useEffect(() => {
    if (id) {
      // ロード処理
    }
  }, [id]);
}

// Component.tsx
useBindingConfig(id);
```

## useEffect の利用基準 (Usage Criteria)

フック内部で `useEffect` を使用して状態を同期させるのは、**外部システム（API、ファイル、メインプロセス等）との副作用処置**を行うべき場合に限定してください。

UI の props による状態変化だけを扱いたい場合は、`useEffect` による同期を避け、以下のパターンを検討してください：

- **コンポーネント分割 + `key` による再マウント**: props が変わったときにコンポーネント全体を初期化したければ、親から `key` を渡して再マウントさせる。
- **props から計算可能な状態（Derived State）への置き換え**: `useEffect` で `useState` を更新するのではなく、レンダリングサイクル内で計算する、あるいは `useMemo` を活用する。

## 適用手順

1.  **引数の定義**: フックの引数に、データのロードや同期に必要な識別子（`id`, `trigger` 等）を追加する。
2.  **フック内 Effect**: 本フックが外部システムとの同期を責務とする場合、フック内部で `useEffect` を定義し、引数の識別子を依存配列に入れる。
3.  **代替案の検討**: 副作用が純粋な React 状態の管理のみである場合、`useEffect` を使わずに `key` 属性や算出プロパティで解決できないか検討する。
4.  **命令的関数の隠蔽**: 外部から呼ばれる必要がなくなったロード関数を `export` から外すか、内部関数にする。
