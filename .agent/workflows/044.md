# [Workflow-044] プリミティブへの抽出 (Primitive Extraction)

## 概要

「実装が似ている」という理由だけで、特定のドメイン（文脈）に特化したコンポーネントを別のドメインで流用（流用）してはいけません。共通の振る舞いがある場合は、ドメインに依存しない**プリミティブ（基本要素）**を抽出し、各ドメインコンポーネントがそれを利用して構成（コンポジション）するように設計します。

## メリット

1.  **意図の明確化**: 名前と用途が一致し、コードの可読性が向上する。
2.  **疎結合**: 特定のドメインの変更が、無関係なドメインの UI に影響を与えない。
3.  **再利用性**: 汎用的なパーツが蓄積され、新規実装が容易になる。

## Bad/Good Example

### Bad (Domain Abuse)

「数値入力だから」と `TimingInput` をマウス座標入力に使い回す。

```tsx
// "Timing" なのに座標を入れているため、意図が混乱する
// また、TimingInput に "ms" 単位がハードコードされている場合、座標にも "ms" が付いてしまう
<TimingInput label="X座標" value={x} />
```

### Good (Primitive Extraction)

共通の数値入力ロジックを `ActionNumericInput` として抽出し、それを使う。

```tsx
// プリミティブ（基本要素）
export const ActionNumericInput = ({ label, value, ...props }) => {
  return (
    <div>
      <Label>{label}</Label>
      <Input type="number" value={value} {...props} />
    </div>
  );
};

// ドメインコンポーネント
export const TimingInput = (props) => (
  <ActionNumericInput {...props} suffix="ms" />
);

// 別のドメインでの利用
<ActionNumericInput label="X座標" value={x} />;
```

## 適用手順

1.  **Smell の検知**: コンポーネント名（例: `Timing...`）と現在の利用文脈（例: マウス座標入力）に乖離がある場合を特定する。
2.  **プリミティブの定義**: ドメイン知識を排除した汎用パーツ（例: `ActionNumericInput`）を `molecules` レイヤー等に作成する。
3.  **再構成**: 元のドメインコンポーネントをプリミティブを使って書き換える。
4.  **移行**: 別のドメインで流用していた箇所をプリミティブ（または新しいドメインコンポーネント）に置き換える。
